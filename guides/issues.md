# Issues

An issue names what happened, what you expected instead, and how to reach it from a clean checkout. Include the version
and the platform.

A question is not a bug. Support-shaped issues get answered and closed with a pointer to where questions go.

Nothing closes on a timer. An issue stays open until it is fixed, answered, or declined. One that cannot be acted on
gets asked for detail once, and closes when the detail does not arrive.

Someone else is assigned? Ask them before you start.

An issue is ready for a stranger when the approach is agreed, the relevant code is linked, the suggested fix is
described, and a test already exists to modify. Short of that it is a todo, not an invitation.
