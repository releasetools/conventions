# Reviewing

Two questions, in this order. Should this exist here? Is it any good? The first
is cheaper to answer and settles more pull requests.

Then read in passes: is the idea sound, is it built right, is it finished.
Raising a polish point before an architecture point wastes the work twice.

Mark every comment. A nit is optional and says so. Anything else blocks, and
says what would unblock it.

No is a complete answer. Say it early, say why, and do not leave a pull request
open because refusing it feels unkind.

Ask rather than accuse. "Am I reading this right?" gets a better answer than
"why did you do this".

If you cannot review a change, hand it on and say so. Silence is the worst
outcome for the person waiting.
